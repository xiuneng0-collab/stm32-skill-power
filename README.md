# STM32 Skill Power

面向 STM32 通用项目的实用 Codex Skill 集合。

这个仓库不是为某一个具体芯片型号、某一块开发板、某一个现成工程，或者某一种复杂硬件场景单独编写的。它的目标，是从最基础、最常见的 STM32 开发工作出发，整理出一套可以长期复用的 Codex Skill 体系，让 Codex 在处理 STM32 任务时更稳、更准、更清晰，而不是一上来就盲目修改、过度设计或者走向复杂化。

这套 Skill Pack 目前包含 5 个核心方向，分别对应 STM32 开发中最常见、最容易反复遇到的问题类型：

## Included Skills

### 1. stm32-project-thinking
通用 STM32 项目的基础思考框架。

这个 skill 负责建立整体工作方式，强调先确认事实、先分层定位、先识别不变量、先缩小问题范围，再决定修改路径。它适合用于分析、调试、适配、review、迁移、说明、问题拆解等几乎所有 STM32 任务，是整个 skill pack 的总入口。

### 2. stm32-debugging
面向 STM32 固件问题排查的调试 skill。

它主要用于处理项目不跑、上电无反应、死机、卡住、无输出、中断不进、DMA 不工作、串口异常、ADC 数值不对、外设不响应、运行不稳定等问题。重点不是“多试几个办法”，而是先判断问题更可能落在哪一层，再用最小代价缩小范围。

### 3. stm32-pin-planning
面向 STM32 引脚规划与实际占用核查的 skill。

它用于整理项目里哪些引脚真的在用、哪些只是配置了但没真正起作用、哪些存在复用冲突、哪些和代码行为不一致。适合处理 GPIO、串口、SPI、I2C、ADC、PWM、定时器、调试口、板级连接器等资源梳理问题，避免被命名、注释或者生成配置误导。

### 4. stm32-migration
面向 STM32 工程迁移与板级适配的 skill。

它适合把旧工程迁到新板、把已有逻辑迁到新的工程骨架、替换硬件连接方式、同步引脚和时钟配置、保留已验证功能并剥离板级差异。这个 skill 的核心思想不是“整包复制”，而是把应用逻辑、驱动层、板级连接、资源差异、工具链配置分开看，减少迁移过程中的误判。

### 5. stm32-peripheral-bringup
面向 STM32 基础外设 bring-up 的 skill。

它主要服务于单个模块先跑通的场景，例如 GPIO 点灯、按键输入、串口打印、定时器中断、PWM 输出、ADC 采样、SPI/I2C 通信、简单 DMA 搬运等。它强调先让一个外设独立可验证，再考虑和更大系统逻辑整合，避免在外设本身还没跑通时就把问题卷进更复杂的业务路径里。

## Design Goal

这个仓库的核心目标不是“教某个型号怎么写代码”，而是约束 Codex 在 STM32 项目里采用一种更可靠的处理方式：

- 先确认真实事实，再相信文件名、注释、自动生成配置或口头描述
- 先分层分析问题，再决定动哪一层代码
- 先保住已验证部分，再处理新变化带来的问题
- 先缩小问题范围，再尝试修改
- 先最小改动跑通，再考虑优化、抽象和重构
- 默认优先简单、稳定、可验证的方案
- 避免还没定位根因就换架构、加封装、加状态层、加复杂中间层
- 避免把临时绕过方案误当成最终设计

## Suitable Scenarios

这套 skill pack 适用于最基础、最常见的 STM32 场景，包括但不限于：

- GPIO 点灯与按键输入
- 串口发送、接收、打印调试
- 定时器与周期中断
- PWM 输出
- ADC 采样与数值检查
- SPI / I2C 传感器通信
- 简单 DMA 数据搬运
- 基础 Flash / EEPROM / SD 卡类存储判断
- 引脚分配整理与冲突核查
- 旧工程迁移到另一块基础开发板
- 上电不跑、卡死、无输出、行为异常等问题定位

## Why This Pack

很多 STM32 问题并不是因为逻辑本身太难，而是因为处理顺序错了：
还没确认事实就开始改代码，
还没分清层次就开始怀疑所有模块，
还没跑通基本路径就开始重构，
还没找到根因就引入更多复杂度。

这个 skill pack 的价值，就是尽量让 Codex 在 STM32 项目里少走这些弯路。

它希望形成一种稳定的默认习惯：
先看清，再下手；
先跑通，再优化；
先解决真正的问题，再讨论更高级的设计。

如果你希望 Codex 在 STM32 项目里更像一个稳健、克制、讲究方法的工程搭档，而不是一个容易过度设计、容易误判方向的助手，那么这套 skill pack 就是为这个目标准备的。
