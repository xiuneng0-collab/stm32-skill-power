# STM32 Peripheral Bring-Up

这份 skill 只做一件事：把单个 STM32 外设先跑起来，再谈系统集成。

## 默认立场

外设 bring-up 默认遵守这几个原则：

1. 一次只 bring-up 一个外设。
2. 先跑最小路径，不要一上来带 DMA、中断、协议封装、业务状态机全套。
3. 先证明外设活着，再证明数据对，再证明集成没问题。
4. 先做最简单的成功案例，再逐步加复杂度。

## Bring-Up 的标准顺序

任何基础外设，默认按这个顺序：

### 1. 确认时钟

- 外设时钟是否开
- 总线时钟是否符合预期
- 相关计算是否正确

### 2. 确认引脚

- 引脚是否真的是该功能
- 复用是否正确
- 是否和别的功能冲突

### 3. 确认初始化

- 初始化函数是否真的调用
- 参数是否真的写入
- 是否存在顺序问题

### 4. 确认启动调用

- 配置不等于启动
- 很多外设“配了但没启动”

### 5. 确认观测方式

- 你是用什么方式判断它工作了
- 这个判断方式本身可不可信

不要在观测方式不可靠时就断言外设有问题。

## 从简单到复杂的加法顺序

默认按这个顺序加复杂度：

1. 最小配置
2. 轮询模式
3. 中断模式
4. DMA 模式
5. 双缓冲或复杂状态机
6. 系统级集成

如果轮询模式都没通，不要直接上 DMA。

## 各类外设的默认 bring-up 路线

### GPIO

最小验证：

- 输出脚能翻转
- 输入脚能稳定读值

优先查：

- 模式
- 上拉下拉
- 端口时钟

### UART

最小验证：

- 先单向发送一段固定文本
- 再验证接收

优先查：

- 波特率和时钟
- TX/RX 引脚复用
- 启动调用
- 接收方式

### SPI

最小验证：

- 先确认 SCK/MOSI 有波形
- 再确认片选时序
- 再看从设备响应

优先查：

- 模式
- 时钟极性相位
- 片选
- 速率

### I2C

最小验证：

- 先确认总线能发起起始条件
- 再确认 ACK
- 再确认寄存器读写

优先查：

- SDA/SCL 上拉
- 速率
- 地址
- ACK / Busy 状态

### ADC

最小验证：

- 先采一个稳定已知输入
- 再看数据范围和变化趋势

优先查：

- 通道映射
- 参考电压
- 采样时间
- 触发源
- 数据对齐

### PWM

最小验证：

- 先确认计数器在跑
- 再确认通道输出
- 再确认频率和占空比

优先查：

- 定时器时钟
- 预分频
- 自动重装
- 通道启动

### Timer Interrupt

最小验证：

- 先确认更新事件产生
- 再确认中断入口执行

优先查：

- 中断开关
- 向量函数
- 定时器时钟
- 清标志逻辑

### DMA

最小验证：

- 先让 DMA 搬一段已知数据
- 再看目标缓冲区是否变化

优先查：

- 源地址 / 目标地址
- 长度
- 数据宽度
- 模式
- 回调

## 常见误区

### 1. 一开始就全链路联调

错误做法：

- UART + DMA + 环形缓冲 + 协议解析一起调
- ADC + 定时器 + DMA + 平滑算法一起调

默认要拆开，先证明底层成立。

### 2. 把“配置成功”当“运行成功”

外设寄存器配上了，不代表：

- 引脚真的输出了
- 中断真的进了
- DMA 真的搬了
- 外部设备真的响应了

### 3. 用错误的现象判断 bring-up 结果

例如：

- 看不到日志，不一定是 UART 不工作
- ADC 数字不稳，不一定是 ADC 坏了
- PWM 没波形，不一定是定时器没跑

先检查观测手段。

## 输出模板

处理 STM32 单外设 bring-up 任务时，尽量按这个顺序输出：

### 当前外设

- 正在 bring-up 哪个外设

### 最小成功标准

- 先达到什么现象才算第一步成功

### 先查什么

- 时钟
- 引脚
- 初始化
- 启动
- 观测方式

### 如果最小路径不通

- 下一步最小验证动作是什么

### 如果最小路径通了

- 下一步加什么复杂度

## 不要做什么

- 不要轮询没通就直接上 DMA
- 不要发送没通就直接调协议
- 不要中断没通就先怪业务逻辑
- 不要 bring-up 一个外设时顺手改一堆别的模块
- 不要一次性把所有高级特性都打开
